How to attach a new intelligence system later

Any future idea (options positioning, fundamentals, social sentiment, a new model) plugs in through one of four doors, and the same rules apply every time.

As context (attach 1–4)

A new market-wide signal, such as option put/call ratio. It becomes a sub-score for the meta-model, never a direct BUY or SELL.

As a filter (attach 8)

A new “stay out” rule. It's shadow-scored from day one, and its verdict on the filter scorecard decides if it stays.

As a setup (attach 6–7)

A new pattern with its own detector and model. It's kept only if it beats “score everything” on the paper stream.

As an explanation (attach 9, 11)

New evidence for or against, shown to users, such as a copilot tool. It changes what users understand, not the decision.

Every door has the same gate: walk-forward and paper evidence, a scorecard with a minimum sample, and your approval in the admin panel's approvals inbox. The locked risk rules (stop, risk per trade, sector cap, drawdown halt) can't be changed through any door.

Algorithm 1 · Nightly decision pipeline (15:45)

every trading day after the daily candles load:
  market  = market_brain.today()                       # regime, trends, breadth, VIX      [1]
  if regime has changed for 2 days in a row:
      regime_change()                                  # re-score, re-rank, re-risk, notify
  phase   = bear_mode.phase(market, market_memory)     # normal · early · decline · panic · recovery   [4]
  sectors = sector_theme_brain.rank(today)             # sectors and themes                 [2]
  universe = active NSE stocks passing liquidity and price floors

  for each stock in universe:
      if data_quality(stock) is below threshold:
          save decision(stock, WAIT, reason = "data incomplete");  continue           [8]
      if landmine(stock):                               # results soon, ASM/GSM/T2T, corporate action
          save decision(stock, AVOID, reason);  shadow_score(stock);  continue        [8]
      features = build_features(stock);  dna = stock_dna(stock)                        [5]
      setups   = detect_setups(stock, features)        # pullback, breakout, momentum, …  [6]
      if no setups:  save decision(stock, NO SETUP);  continue
      for each setup s:
          p_setup = setup_model[s].predict(features)   # + time-horizon heads             [7]
          p_win   = meta_model(rule_score, p_setup, market, sector, news, risk_quality)   [9]
          exp_r   = p_win × avg_win(s, regime) − (1 − p_win) × avg_loss(s, regime) − costs [10]
          agree   = models voting BUY ÷ models voting                                      [11]
          state   = decide(p_win, exp_r, agree, phase, entry_zone)
          save decision(stock, s, p_win, exp_r, agree, state,
                        evidence_for, evidence_against, trigger = signal_high × 1.0025)

  ranked = TRADE decisions ordered by exp_r, highest first
  for each book (bot paper/live, and each user's view):
      fit = portfolio_fit(ranked, holdings, correlation, sector cap, deployable %)   [12]
  publish decisions to the product stack (one way)

Algorithm 2 · Deciding the state

decide(p_win, exp_r, agree, phase, entry_zone):
  if exp_r ≤ 0 or risk quality is poor:     return AVOID
  if agree below 4 of 6, or phase is panic,
     or an event is due, or regime changing: return WAIT
  if price is 3%+ above the entry zone:     return WATCH  "wait for pullback"
  if p_win ≥ min_conf(phase)
     and exp_r ≥ min_edge:                   return TRADE
  otherwise:                                 return WATCH

min_conf: 0.60, plus 0.10 in a NIFTY downtrend (today's rule)
min_edge, 4-of-6 and 3%: starting values, tuned by walk-forward

Algorithm 3 · Sizing (today's rule, kept)

risk_rupees  = capital × risk_per_trade        # 1%, locked
qty_by_risk  = floor(risk_rupees ÷ (entry − stop))
qty_by_alloc = floor(allocation ÷ entry)
qty = smallest of qty_by_risk, qty_by_alloc,
      single-stock cap, cash above the cash floor
if deployable % is used up, or drawdown ≥ 15%:
      qty = 0                                   # no new entries; exits continue

Algorithm 4 · Trigger entry (test T1)

next session after a TRADE decision:
  if price trades above trigger and volume pace ≥ 1.5×:
      buy with a limit just above trigger
  else at the close:
      trigger expires; record EXPIRED (still scored)

What this document is

SwingTradeML grows from a stock-scoring signal generator into a market decision-intelligence platform.

It reads the market, then the sector, then the stock. It decides TRADE, WATCH, WAIT or AVOID with evidence for and against, and it learns from every outcome. This is the single document for the product, the AI and the build plan.

Keep the existing engine → expose what it already does → fill the missing intelligence layers → measure every new model against today's baseline.

Where v3 differs from the review

One meta-model, not stacked adjustments

The review adds news, sector and risk as separate steps, such as “Decision impact +7%”. Stacked adjustments double-count and break calibration. In v3 every input feeds one meta-model, calibrated on walk-forward folds. The pipeline diagram shows reading order, not maths order.

News impact numbers need history

“Historical similarity 82%, typical 10-day impact +4.1%” needs years of classified announcements, and that history starts the day we record it. Classification ships in Month 5; impact numbers come later as event-impact learning (F34).

The user profile doesn't change a stock's DNA

The review draws User Brain → Stock DNA. DNA is a shared fact about a stock, the same for everyone. In v3 the User Brain feeds personal ranking, portfolio correlation and risk sizing instead.

The priority list skips the gates

The review's P0 is all intelligence. v3 keeps that order for the intelligence track, but on the owner's paper book first. No public calls before SEBI registration and a data licence, and no real-money claims before the edge is proven.

Fundamentals aren't available yet

The review lists Fundamentals in the Data Brain. There is no point-in-time source today; NSE XBRL parsing is a multi-week project in the 12-month plan.

Per-stock percentages need samples

“Breakout 78%” for one stock needs enough past breakouts in that stock. v3 shows them only with 20 or more past setups, pulled toward the sector average, with the sample size on screen.

Bear market memory and playbook · F35, F36

A bear market should be a known situation, not a surprise

The app remembers every past weak phase: how deep and long it was, what our system did, and what it lost. When a similar phase starts, it shows the closest past episode, switches to a tested defensive playbook, and tells each user what it means for their holdings.

Defences already built

  • Regime table cuts deployable capital to 30% in a weak market and 10% when stressed (deployable.py)
  • Confidence bar raised by 0.10 in a NIFTY downtrend (bear_market_confidence_boost)
  • Falling-knife, liquidity and volatility filters (ml_swing.py)
  • 15% drawdown halt on new entries, never force-selling
  • Sector cap, cash floor, 30-day time stop

What's missing

  • No measurement by market phase. The replay (May 2023 – Aug 2026) reports averages per 8-month window, never “during the correction we lost X”.
  • Defences not replayed. The replay skipped the regime deployable %, sector cap and cash floor, so we don't know how much they protect.
  • No memory. Nothing stores past episodes or compares today with them.
  • No bear-market experience for users. Fewer picks appear with no explanation.

4 · If it repeats: questions the memory must answer

How much did we lose, and why?

Per episode: system result vs NIFTY, the loss labels, and which setups failed. From the episode replay, not averages.

Which defence saved the most?

Replay each episode with one defence switched off at a time: regime limit, confidence bar, drawdown halt, filters.

What still worked?

Setups, sectors and cap tiers that made money in each episode. They become the bear-mode shortlist.

Would a different playbook do better?

Test alternatives on some episodes, confirm on episodes they weren't tuned on, and check they don't hurt normal markets.

What happens to my portfolio?

Replay a past episode's actual daily moves on the user's current holdings (extends the what-if simulator).

How long did recovery take?

Days to bottom and to recover per episode, shown as history, never as a promise.

Experience engine · F37, F38, F39

After a few months the app should know from its own evidence which scores, factors and filters work, and in which market. That evidence comes from two places: history replayed over five years of stored data (available now) and the app's own daily testing (grows every day).

A score can't make returns mandatory. Markets can't be guaranteed, and SEBI prohibits promising returns. 3 · The lessons loop: better every bear market · F39

What “successful” means in a bear market

Lose much less than the market, lose less than in the last similar episode, and keep capital ready for the recovery. Profit in a falling market is welcome but not the target.

Measured every episode

  • Our fall vs NIFTY's fall (target: less than half)
  • Loss vs the previous comparable episode
  • Cash available at the bottom
  • Days to regain the previous high

Applied next time

In bear mode the shortlist favours the factors, setups and sectors whose scorecards were positive in past weak phases. The closest-episode card shows which lesson is being applied.

Architecture · frozen for v3

Data Brain and User Brain feed one decision pipeline

Shared facts flow down the centre. Personal context joins only where ranking, portfolio and risk are decided. Every decision ends in the journal, which feeds the learning loop back to the models.

A existsB exists, extendC newD future Dashed purple: learning loop, only through human approval

Engineering rules carried over from the codebase

Risk rules stay locked

Stop, target, risk per trade, sector cap, time stop and the 15% drawdown halt can't be changed by any profile, plan or user setting. Enforced in types (extra="forbid").

Off by default, byte-identical

Every new layer ships behind a flag. With the flag off, the scan output must be byte-identical to today's, proved by a snapshot test.

Point-in-time data

Every feed is stored with its fetch date. News and order-book history start the day we start recording.

Walk-forward or it doesn't ship

A new model must beat the current one on purged walk-forward folds and on the paper stream.

One meta-model

News, sector, regime and risk enter one calibrated model as inputs, never as stacked percentage adjustments.

Failures are visible

A stale feed raises an alert and lowers data quality. Low data quality means no decision.

Data model

Shared facts once, personal data by owner

Market tables have no user column and are computed once a day. Personal tables hang off users through a portfolio, watchlist or broker connection, and every /me/* route filters by the signed-in user.
