    Part A · V1 · the system as built today

    One DigitalOcean droplet runs five Docker containers. Only the worker runs the scheduler, so two schedulers can never race to place the same trade. Production configuration lives on the droplet at /root/app/.env, not in git.

    Figure 1.1 · Containers and outside servicesdocker-compose.yml + docker-compose.prod.yml

    The worker talks to Kite, NSE and Telegram; the API serves the dashboard and handles the Kite login callback. GitHub Actions deploys over SSH.

    Figure 1.2 · From a push to a verified release.github/workflows · infra/deploy/release.sh

    The same image starts both the API and the worker. What differs is one setting: whether the scheduler runs. Live trading needs two separate settings to be true.

    Sizing (services/risk.calculate_quantity)
risk_rupees  = account value × RISK_PER_TRADE_PCT (1%)
qty_by_risk  = floor(risk_rupees ÷ (entry − stop))        stop = entry × 0.96
qty          = smallest of qty_by_risk, allocation ÷ entry,
               single-stock cap (limits_for), cash above the cash floor
limits_for(account value) interpolates the ₹10K → ₹1Cr capital ladder:
               max positions, single-stock cap, sector rule, cap tiers,
               small-cap budget, cash floor, liquidity ceiling

    Part B · V2 · TradeMind product with Free, Plus and Pro (designed, not built)

    V2 keeps V1's engine as a private trading core and adds a public product stack for users. The core publishes each day's intelligence one way; the product never holds your Kite trading secrets.

    Figure 13.1 · Trading core, product stack and stagingdeployment design
    Migration stepMonthTechnical change
    1 · Measure and log1Journal and shadow scoring switched on; episode replay; decision_records table
    2 · Intelligence on paper2–3Setup detectors, EV, meta-model behind flags; scan byte-identical when off
    3 · Staging and accounts3users.role; portfolios, watchlists, broker_connections; owner migrated as user 1
    4 · Product stack split4New stack; one-way publish; admin panel; billing in test mode
    5 · Licensed data, private beta5Vendor feed for user-facing prices; owner on real holdings
    6 · Launch decision6Public Free and Plus only if SEBI registration, data licence and paper evidence are all in place

    The V1 scan (chapter 6) becomes a pipeline with twelve attach points [1]–[12] where intelligence plugs in. Every new step ships behind a flag; with the flags off, output is byte-identical to V1.

    Figure 14.1 · 15:45 decision pipelinetrading core
    decide(p_win, exp_r, agreement, phase, entry_zone):
  AVOID  if exp_r ≤ 0 or risk quality is poor
  WAIT   if agreement below 4 of 6, panic phase, event due, or regime changing
  WATCH  if price is 3%+ above the entry zone ("wait for pullback")
  TRADE  if p_win ≥ 0.60 (+0.10 in a NIFTY downtrend) and exp_r ≥ min_edge
  WATCH  otherwise                       (thresholds tuned by walk-forward)
