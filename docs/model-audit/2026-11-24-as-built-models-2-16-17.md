## How the evidence was gathered

* The saved model files are **not in the repo checkout**. `backend/data/models/` in this checkout holds only `.scheduler_*` files. The 21
  `fd_h5_*.joblib` and 18 `wf_h15_*.joblib` files found under other worktrees are research files, not models 2/16/17.
* The three files were found inside the two running **local** Docker API containers, `/app/data/models/` of
  `swingtrademl-main-local-api-1` and `swingtrademl-stable-api-1`. They were copied out read-only with `docker cp` into the session
  scratchpad (not the repo) and opened with the repo venv Python (`-I`). The files in both containers have identical sha256.
* Registry rows come from a `SELECT` on the local dev DB `swing_trade_ml` in container `stml-postgres`. The stable snapshot DB
  (`swing_trade_ml_stable`) returned identical rows for ids 2, 16 and 17. Nothing was written.
* Training code was read from git history (`git show abc9c0b:...`, `git show 7da460c:...`) because the code that trained the models
  is **not** the code on this branch today (see D1, D2).
* No prod access of any kind; `.env` was not read.

### Runtime scoring path (model 2)

* v1 `ml_swing`: `strategies/ml_swing.py:97` picks the ACTIVE model by `params.model_name`; `:102-117` loads candles, index, sector, VIX and breadth frames bounded to the bar and runs `build_features` (today's code); `:117-119` takes the saved column list `bundle["feature_names"]`; a NaN row means no score (`:120-121`); `:123-131` `scaler.transform` then `estimator.predict_proba(...)[0,1]` is the score. `ml/predict.py:69-118` (`predict_instrument`) does the same on the newest 400 bars and needs at least 220 (`:77-80`).
* Brain: `brain/reader.py:42` `FALLBACK_MODEL_NAME = "swing_classifier"`, `:470` loads it, `:476` calls `predict_instrument`, `:495-496` returns probability and buy level; `brain/fallbacks.py:117-145` turns it into an opinion (stance = 2p - 1). So **the brain's score for every stock, whatever its size, is model 2** (same statement in `docs/ARCHITECTURE_REVIEW.md:226-229`).
* Calibration: none. Uncalibrated `predict_proba`. "Score out of 100" is the probability times 100 as a display; the full probability-to-display trace is #226's task.
* Fallbacks: no model row or file means no score (`ml_swing.py:99-101`, `reader.py:477-482`); the brain then has no opinion.
* h05 lane: `brain/lanes/h05_models.py:92-155` re-verifies registry row, sha256 (`:124-125`), input list (`:128-129`), label (`:134-135`) and "no stop, not calibrated" (`:136-139`) before any run.
* Known skew (not repeated here): `obv_slope` has been served with a different formula than the model was trained on since 2026-10-06 (`ml/features.py:296-300`, `docs/superpowers/specs/2026-10-30-obv-slope-incident.md`). Tracked by #272 and #226.

## Discrepancies (docs, issues or memory versus code or artifact)

* **D1. Today's training code cannot reproduce these models.** `ml/train.py` on this branch always builds the barrier label (default 15 bars, +8%, -4%;
  `ml/features.py:372-376`; `ml/train.py:386,406`), splits on a date boundary with a purge (`ml/dataset.py:150-172`), and the word "endpoint" does not
  appear in `ml/features.py`, `ml/train.py` or `ml/dataset.py`. The saved models came from the August 2026 code (row-count split, no purge, endpoint label,
  commits `abc9c0b` / `7da460c`). Current defaults `ML_PREDICTION_HORIZON_DAYS=15`, `ML_TARGET_RETURN_PCT=0.08` (`core/config.py:282-283`) would give a different model.
* **D2. `docs/ARCHITECTURE_REVIEW.md:213-216`** ("embargo = horizon", walk-forward folds) describes today's `train_model`, not how these three were trained: they had no embargo and no walk-forward.
* **D3. No training commit is stored.** Model 2 was trained 2026-08-05 15:02 IST, between `abc9c0b` (08-04 15:33) and `7da460c` (08-06 16:58). Its 37 inputs equal
  `abc9c0b` exactly, so it is consistent with that commit, but it may have been trained from an uncommitted working copy.
* **D4. `label_kind = endpoint` is a migration default, not a recorded fact** (`alembic/versions/20260915_1040_barrier_label_definition.py:31`). The artifacts carry only `horizon_days`
  and `target_return`. The endpoint definition rests on code history; it does agree with `h05_models.py:107-109` and the docs.
* **D5. Registry `hyperparameters` is `{}` for all three.** Any doc calling them "tuned" or "recorded" is wrong; the values are code defaults (verified in the artifact).
* **D6. Model 16 v2 is a byte-identical duplicate of v1 (id 15)**, trained 75 seconds earlier. "v2" does not mean a retrain or an improvement.
* **D7. Universes versus scored stocks.** Models 16/17 were trained on 24/30 stocks, but the local strategies 4/5 list 150/104 stocks (overlap 24 and 30), and strategy 1 lists 52
  against model 2's 49. Most stocks the mid and small models score were never in their training data. (Local DB; prod lists were not read. The h05 lane builds its own universe
  from the active strategy lists, `h05_models.py:169-206`.)
* **D8. Date in the incident note.** `docs/superpowers/specs/2026-10-30-obv-slope-incident.md` gives model 17 as trained 08-20; in IST it was 2026-08-21 00:04 (18:34 UTC on 08-20). Mixed UTC and IST only.
* **D9. Frozen hash source.** `h05_protocol.py:36` says the hashes were read from the production backup zip on 2026-10-30. This audit confirms the **local** files equal those hashes;
  it cannot confirm prod itself.
* **D10. Library mismatch.** The artifacts were pickled with scikit-learn 1.9.0; the repo venv and the containers load them with 1.9.1 (`InconsistentVersionWarning`). h05 records library
  versions per run (`h05_models.py:69-74`); prod's versions were not checked.
* **D11. No discrepancy found** on: 37/46/46 input counts, 49/24/30 symbol counts, +2% / 5 bars / no stop, uncalibrated, LightGBM. Listed so the check is on record.
